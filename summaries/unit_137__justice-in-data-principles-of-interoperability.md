# Justice in Data: Principles of Interoperability

Foundation-level module on standards, integration, and interoperability, taught by Professor Sharma Chakravarthy (introductory team presentation, no prior interoperability knowledge assumed). Resources: slide deck `CTW-interoperability_FINAL.pdf` ("Introduction to Interoperability Slides"), a Principles of Interoperability Pre-Survey (utaedu.questionpro.com survey link), and a full lecture recording with transcript (YouTube video p58kV6sFFgU). Outline: standards/integration/interoperability with familiar examples; why it matters (healthcare-domain video); application interoperability; data usage; how FAIR principles affect interoperability; conclusions.

**Standards:** definitions and standards bodies (IEEE, ANSI, ISO 9000, ISO/IEC, ASCII, OGC with 30+ standards, W3C); examples USB A/B/C, SATA, SCSI, XML, HTML, SQL. Benefits of standard interfaces (clutch/brake/accelerator analogy); costs of non-standardization: electrical plug converters, Apple's proprietary interface, the Great Baltimore Fire of 1904 (30% of hoses would not connect), standards wars (Betamax vs VHS). Software standards enable compatibility; Javadoc is discussed as a documentation guideline (not a standard) with a SuperHero/Person Java example and Berkeley Minibase Javadoc reference; software documentation quality, Oracle DBMS (1M+ lines of code), and NASA software trustworthiness are mentioned in the lecture.

**Integration vs. interoperability:** pairwise application integration via APIs incurs the quadratic cost problem; middleware and a common language reduce it to linear cost. Examples: point-of-sale/market-basket data plus customer data for CRM; UN General Assembly interpreters vs. a single common language (Esperanto); Google Flights-style flight aggregators using published airline APIs (Southwest does not publish its APIs); DoD in the 70s/80s with hundreds of programming languages and heterogeneous databases, schema integration research, the Ada language (named for Ada Lovelace) mandated across DoD, and DoD funding of the Oracle relational DBMS. An embedded healthcare YouTube video (eLK0UL2WYN8) on "standards and interoperability in digital health" follows Lucy (national immunization officer) and Isaac (district health officer of Umbaya) in fictional Onessa planning a child vaccination campaign: OpenLMIS (supply chain) and DHIS2 (district health information) cannot exchange DPT vaccine data; semantic standards (vocabulary, e.g. vax.DPT, facility145) and syntactic standards (grammar), and a Health Information Exchange (HIE, e.g. OpenHIE) as central translator overcome the quadratic cost.

**Levels of interoperability:** foundational (tightly integrated), structural (syntax/format of exchange), semantic (exchange plus use of information — highest level).

**Open vs. FAIR data:** FAIR data must be discoverable in online public records, accessible (openable/readable/processable), and understandable via metadata; FAIR principles apply to metadata too; data interoperability defined per the Open Data MOOC (easily retrieved, processed, re-used, re-packaged).

**Data exchange formats:** markup languages HTML, XML, RDF/XML; formats XML, JSON, YAML, CSV, TSV, RDF; CSV/TSV usable directly in Python/Pandas. XML pros/cons (W3C standard, human readable, DTD error checking, style sheets, hierarchies; bulky, CPU-intensive parsing), DOM and XPath querying, native DBMS XML support, with a PAKDD2022 paper-review XML example ("Object Detection via Inner-inter Relational Reasoning Network"). JSON (JavaScript Object Notation) syntax rules with an employees-array example. CORBA (Common Object Request Broker Architecture) covered for completeness (binary, language/OS independent, high learning curve, firewall issues). USGS/OGC case study: USGS data services get over 1M hits/day; OGC interoperability assessment included compliance testing against the OGC Compliance Engine, virtual-exercise use cases via a Call for Participation (CFP), and a CAT 3.0 test suite developed on GitHub.

Conclusions: data is of limited use unless findable, accessible, understood, and usable; FAIR principles plus standards ease analysis. Next module covers metadata and provenance.
