# Containers and Virtual Machines

Expert-level module contrasting virtual machines (VMs) and containers.

**Text content — "Why Virtual Machines?"**: VMs let you explore operating systems without changing your own, safely weed out malware, and run old OSes for incompatible software; their portability across hardware benefits multi-person projects and businesses changing computers, though Docker has lately overshadowed this. Recommends trying Linux (Ubuntu is shown; Linux is covered in Module 2). **"Containers and Docker"**: a container sets aside disk space for bins and applications run through the host OS rather than a full guest OS, making containers less resource-intensive than VMs while keeping applications and code portable. Docker is a company providing access to containers, including over the cloud. A linked article shows how containers help EAPS science.

**Fetched resource 1: "How to Create and Use Virtual Machines" (link)** — How-To Geek beginner article by Chris Hoffman (howtogeek.com). Explains that a VM app creates a virtualized environment with virtual hardware; guest OS vs host OS terminology; guest stored on a virtual hard drive file; virtualization overhead makes VMs poor for demanding games. Reasons to use VMs: experimenting with other OSes (e.g., Linux distributions), running another OS's software (Windows apps on Linux/Mac, Windows XP apps under Windows 10), and sandboxing untrusted apps/websites (e.g., testing "Hi, we're from Windows" tech-support scammer software safely). Surveys VM applications: VirtualBox (free, open-source; Windows/Linux/Mac OS X), VMware Player (free; Windows/Linux) and paid VMware Workstation, VMware Fusion and Parallels Desktop (Mac OS X), plus Linux KVM and Microsoft Hyper-V (Windows 8/10 Professional and Enterprise). Walks through VM setup in VirtualBox: creation wizard, OS type/version selection, memory allocation, virtual hard disk creation, dynamically allocated vs fixed-size disks (fixed recommended for performance), and booting from an ISO file. Links further guides on speeding up VMs, Hyper-V, Android in VirtualBox, file sharing, and Portable VirtualBox.

**Fetched resource 2: "Using Linux containers to analyze the impact of climate change and soil on New Zealand crops" (link)** — Opensource.com article by Eric Burgueño (also a linux.conf.au talk, Christchurch, New Zealand). Describes agricultural systems models such as CropSyst (Washington State University) and APSIM, the Agricultural Production Systems Simulator (CSIRO, Australia). New Zealand Crown Research Institutes — Landcare Research, NIWA (National Institute of Water and Atmospheric Research), and the New Zealand Institute for Plant & Food Research — contributed soil, terrain, climate, and crop-model datasets to run millions of APSIM simulations covering >100 years of climate-change data across New Zealand at ~25 km² resolution. Covers HPC (high-performance computing), batch processing, job schedulers (PBS, HTCondor, Torque, SGE, Platform LSF, SLURM), embarrassingly parallel workloads, and the OpenHPC project. APSIM's dependency hell: Mono Project framework for Windows/Linux portability, binfmt_misc kernel module for .exe execution, undocumented dependencies targeting Ubuntu Desktop. Containerization benefits for reproducible research: reproducibility, portability, immutability. Docker iterations included multi-stage builds; Docker drawbacks for multi-tenant HPC: data ownership (containers run as root or hardcoded UIDs; docker run -u workaround), access to persistent storage (bind mounts/volume mounts per container), and compute host security (root-privileged daemon violating the Principle of Least Privilege; user namespaces as an awkward fix). Singularity (Singularity Community, released 2016) solves these: users inside the container are the same user as outside, single executable image files, native import of Docker images from Dockerfiles. A worked "day in the life" example contrasts clunky docker run commands (with -v mounts, SELinux :z flags, UID/GID mapping, qsub job submission on a CentOS 7 cluster vs Ubuntu Bionic) against a simple singularity pull workflow. Results are collated in a MariaDB database and visualized in an RStudio Shiny web app comparing climate scenarios (e.g., baseline 1985–2005 vs end-of-century 2085–2100 silage maize biomass across New Zealand arable lands), with variables for climate projections, soil, irrigation, fertilizer, and sowing dates.

- **How to Create and Use Virtual Machines** (https://www.howtogeek.com/196060/beginner-geek-how-to-create-and-use-virtual-machines/, remote resource): How-To Geek beginner tutorial by Chris Hoffman explaining virtual machine basics including the difference between host and guest OS, virtual hardware simulation, advantages of sandboxing for testing untrusted software, and detailed setup instructions for creating VMs in VirtualBox with guidance on disk allocation and optimization.

- **Using Linux containers to analyze the impact of climate change and soil on New Zealand crops** (https://opensource.com/article/19/1/using-containers-analyze-climate-change, remote resource): Opensource.com article on containerizing agricultural systems models (APSIM) using Docker and Singularity for large-scale climate impact simulations, comparing container technologies for HPC environments and demonstrating real-world workflow simplifications when using Singularity over Docker for multi-tenant scientific computing.
