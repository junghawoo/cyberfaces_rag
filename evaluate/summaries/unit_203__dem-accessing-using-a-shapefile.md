# Geospatial & Hydrological Science: DEM Accessing using a Shapefile

## Summary

This module covers Geographic Information Systems (GIS) fundamentals using QGIS (free, open-source software), spatial data types, and practical workflows for accessing and processing USGS Digital Elevation Models (DEMs) via Python Jupyter notebooks. Instructors include Jibin Joseph and Venkatesh Merwade (Lyles School of Civil Engineering, Purdue University). The module is part of FAIR Science in Water Resources training and supports the CyberFaCES platform.

**QGIS Introduction & Access:** QGIS is free and flexible software running on Windows, macOS, and Linux (including HPC clusters), with no licensing fees, extensive documentation, large active community support, rapid development, and capabilities for extending with AI/GeoAI. QGIS offers vector/raster analysis, geoprocessing, geocoding, georeferencing, web mapping, 3D visualization, and support for Shapefile, GeoTIFF, GeoJSON, WMS, WFS, PostGIS formats via GDAL/OGR libraries. QGIS is launched on clusters via two methods: (1) Interactive ThinLinc client access—select "Cluster Software" > "QGIS", choose "workshop" queue, input cores (e.g., 2) and time (e.g., 5 minutes); memory scales proportionally with cores unless explicitly specified with units (e.g., "4G"); (2) Command-line via terminal—module spider qgis to find module, then sinteractive -A workshop -N1 -c8 -t8:00:00, module load qgis, qgis. Gateway (Open OnDemand) at https://gateway.negishi.rcac.purdue.edu provides web interface with file explorer and interactive QGIS apps accessible with personal Purdue accounts after creating cluster accounts.

**Spatial Data Types:** Vector data represents discrete features using geometric objects—points (locations like cities, trees), lines (roads, rivers), and polygons (lakes, buildings, administrative boundaries)—with high precision and scalability without quality loss. Vector formats include Shapefile (.shp, actual collection of .shp, .shx, .dbf, etc. files), GeoJSON (JSON-based open standard), KML/KMZ (Google Earth), and formats supported by GDAL/OGR. Raster data represents continuous phenomena as grids of cells/pixels with values (elevation, temperature, land cover), ideal for spatial analysis, modeling, and calculations. Raster formats include TIFF (basic image without geospatial metadata), GeoTIFF (TIFF + geospatial metadata), COG (Cloud Optimized GeoTIFF with tiled structure for fast cloud access), and formats via GDAL/OGR. Key differences: vector uses geometric shapes (discrete), raster uses grids (continuous); vector precision depends on feature boundaries, raster precision depends on cell size; vector typically requires less storage for discrete features, raster storage heavily dependent on resolution. DEM is raster data representing bare earth surface after removing natural/built features, created via ground surveys, digitizing hardcopy maps, or remote sensing, used for watershed delineation, topographic characteristics (slope, drainage density, topographic index), and hydraulic/hydrodynamic flood modeling.

**Loading Spatial Data in QGIS:** Loading vector data: Layer > Add Layer > Add Vector Layer, input shapefile path (e.g., alaska.shp), hit "add"; layers panel displays loaded shapefile. Loading CSV files: Layer > Add Layer > Add Delimited Text Layer, specify delimiters and coordinate columns (X, Y fields) with appropriate settings, hit "add". Loading raster data: Layer > Add Layer > Add Raster Layer, input raster path (e.g., landcover.img, SR_50M_alaska_nad.tif for Hillshade GeoTIFF), hit "add"; layers panel displays raster. QGIS attempts to identify Coordinate Reference System (CRS) from shapefile .prj files; if missing, prompts user specification. CRS behavior is configurable in Settings > Options > CRS to automatically assign project CRS or designated default CRS. Challenges include identifying orientation issues (e.g., Hillshade displaying in wrong hemisphere) resolved via Layer Properties and look adjustments.

**Spatial Data Processing:** Vector filtering uses right-click > Filter, selecting fields (e.g., ELEV for elevation), and inputting filter expressions (e.g., "ELEV" < 1000) to restrict features; example filters Alaska airports with elevation < 1000 feet for health considerations. Filtered data is exported via right-click > Export > Save Features As, saving as new shapefile with specified format/CRS. Raster calculation uses Processing Toolbox > "Raster Calculator" search, specifying Input Layers, Expression (e.g., "Hillshade" < 100 for sunny slopes), Output CRS, and calculated output filename; results visualize with customized rendering. Raster results export via right-click > Export > Save As with format/CRS specification. QGIS Desktop integration enables interactive spatial manipulation suitable for learning.

**DEM Access Tutorial (Python/Jupyter Notebook):** The detailed tutorial (Instructions PDFs v05/v07/v08, Solution Notebook v4) guides accessing USGS DEM tiles for watersheds via Python-based Jupyter on CyberFaCES platform. Prerequisites: CyberFaCES login (www.cyberfaces.org, supporting CILogon institutional credentials, Google Account, ORCID). Computer Requirements: Python with conda environment including pynhd (accessing shapefile via USGS site number), urllib (accessing DEM data), progressbar (tracking large file downloads), rasterio (plotting unmerged raster tiles), plus standard packages (math, numpy, matplotlib, geopandas, shapely). Workflow steps: (1) Input USGS site number (e.g., "04180000" Driftwood River near Edinburgh, Indiana, 1062 sq. mi drainage area; "03335500" with 7267 sq. mi needs more time/space; "02273000" Kissimmee River near Okeechobee, Florida; "01502632" Susquehanna River at Bainbridge, NY; "06186500" Yellowstone River at YNP outlet, WY) and desired resolution (USGS-AWS options: 1/3 arc second code=13, 1/9 arc second code=19 unavailable); create directory via check_create_path_func() to store files; (2) Use pynhd.NLDI().get_basins(site_id) to retrieve watershed shapefile, plot with facecolor/edgecolor specifications, save as shapefile; (3) Generate inset map with Contiguous US and state boundaries using centroid calculation to identify HUC-2 region; (4) Extract shapefile bounds using four bounding box coordinates (min/max latitude/longitude); (5) Create list of DEM raster tile pairs (latitude/longitude integers) intersecting watershed; (6) Define progressbar function for download tracking; (7) Generate filenames from extents, retrieve files from USGS-AWS portal (https://prd-tnm.s3.amazonaws.com/) via urllib module sequential download; execute cell with internet speed dependence (files saved to raw_<site_id> folder); (8) Implement multithreading for concurrent download (3x speed improvement typical vs. sequential) using threading module; (9) Plot unmerged raster tiles with watershed shapefile using rasterio to visualize successful download/overlap; output stored in input_<site_id> directory. Output organization: /data/jobid/1 (downloaded NetCDF files), /data/jobid/2 (shapefiles), /data/jobid/3 (processed results, moved to /geoedf/workflows/jobid/output). DEMs downloaded are not projected or clipped to watershed boundary; processing is covered in separate DEM processing module. Challenges addressed: Jupyter kernel verification (ct-fair preinstalled with all modules); Earthdata account requirement for MODIS access (example account rkalyana); troubleshooting code execution and folder creation. References include: Hawker et al. (2018) DEM simulation for flood modeling (Frontiers in Earth Science 6:233); Saksena & Merwade (2015) DEM resolution/accuracy for flood inundation (Journal of Hydrology 530:180-194); Chegini et al. (2021) HyRiver: Hydroclimate Data Retriever (JOSS 6(66):3175); Python urllib.request documentation; Rasterio documentation (Gillies, 2019, MapBox).
