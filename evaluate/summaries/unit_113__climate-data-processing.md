# Climate data processing in Python

Tutorial module on efficient climate data processing in Python using xarray, Cython, and Dask, prepared by Qinqin Kong and Matthew Huber (Department of Earth, Atmospheric, and Planetary Sciences, Purdue; kong97@purdue.edu). Instruction PDF: `Instructions_for_climate_data_processing.pdf`. Motivation: massive climate model output is too large for memory (solved by Dask chunked/parallel computation) and pure Python is slow (solved by Cython compilation to machine code plus Dask parallelism).

Course materials are two Jupyter notebooks — `Climate_data_processing_using_xarray_dask_cython_mygeohub.ipynb` and `Using_Cython_to_speed_up_your_python_code_mygeohub.ipynb` — available via the "FAIR Climate and Water Science" course page on MyGeoHub and on mybinder.org (QINQINKONG/cybertraining_workshop repo). Pre-recorded videos on the Climate Dynamics Prediction Lab YouTube channel (two linked YouTube videos). Fetched notebook sources live in the PurdueCyberTraining/fairclimatewater GitHub repo (DP8 and DP9 folders).

**Cython notebook** (Using_Cython_to_speed_up_your_python_code): reads CMIP6 data from the cloud with intake-esm (`intake.open_esm_datastore` on the Pangeo CMIP6 catalog, pangeo-cmip6.json on Google Cloud Storage), querying model KACE-1-0-G (NIMS-KMA), experiments historical and ssp585, 3hr table, variables tas/huss/ps, member r1i1p1f1, loaded via zarr. Defines pure-Python wet bulb temperature functions following Bolton (1980, Monthly Weather Review) and Davies-Jones (2008, Monthly Weather Review): esat, mixrsat, vaporpres, lcltemp, thetadl, thetae, wb1stguess, f, dfdT, fwb, wetbulb_py, using scipy.optimize.brentq. Teaches Cython compilation stages (.pyx to .c to .so), %%cython magic, static typing (cdef/def/cpdef functions), typed memoryviews and contiguous memoryviews, @cython.boundscheck/@cython.wraparound decorators, calling C libraries (libc.math), OpenMP parallelism with prange (compile args -fopenmp, -Ofast), scipy.optimize.cython_optimize brentq, and comparison with Numba @njit/vectorize. Benchmark progression: ~30% speedup from compilation alone, 5x from typed variables, 200x with typed functions; final wetbulb_cython achieves near 200x speedup. Guidance: use Cython for non-vectorizable bottlenecks, not simple array math where NumPy wins.

**xarray/Dask notebook** (Climate_data_processing_using_xarray_dask_cython): same CMIP6 wet-bulb workflow comparing year 2000 (historical) vs 2100 (ssp585). Introduces Dask chunking with xarray (`.chunk({'time':200})`), lazy evaluation with load()/compute(), single-machine vs distributed schedulers, dask.distributed Client, threads vs processes and the GIL, `xr.apply_ufunc` with dask="parallelized" for custom functions, and multi-node clusters via dask_jobqueue SLURMCluster (queue/project "huberm", cluster.scale, cluster.adapt). Includes Dask best practices: avoid unnecessary distributed clusters, start small, use the dashboard, chunk sizing (~100MB), avoid too many tasks. Final workflow applies wetbulb_cython through apply_ufunc, writes results to NetCDF (wb_ssp.nc, wb_hist.nc), and computes changes in annual mean and 95th percentile wet bulb temperature (mean_diff, q95_diff merged and saved to output.nc). Also uses fsspec, numpy, xarray tutorial dataset air_temperature.

## Summarized attachments

- **Instructions_for_climate_data_processing.pdf** (`Instructions_for_climate_data_processing.pdf`, file): PDF instructions prepared by Qinqin Kong and Matthew Huber (Purdue Department of Earth, Atmospheric, and Planetary Sciences) outlining the objectives and motivation for efficient climate data processing: handling massive climate model output that exceeds available memory (solved via Dask), and accelerating pure Python code (solved via Cython compilation). Specifies the complete workflow, required Python packages (xarray, rasterio, geopandas, cython, dask, intake), and links to supporting Jupyter notebooks on MyGeoHub and mybinder.org.

- **Using_Cython_to_speed_up_your_python_code_mygeohub.ipynb** (https://github.com/PurdueCyberTraining/fairclimatewater/blob/main/DP9/Using_Cython_to_speed_up_your_python_code_mygeohub.ipynb, Jupyter notebook): Interactive notebook demonstrating Cython compilation techniques for accelerating Python code. Reads CMIP6 data from the cloud using intake-esm (querying KACE-1-0-G model, historical and ssp585 experiments, 3hr resolution, tas/huss/ps variables via zarr on Google Cloud Storage). Defines pure-Python wet-bulb temperature functions (esat, mixrsat, vaporpres, lcltemp, thetadl, thetae, wb1stguess, f, dfdT, fwb, wetbulb_py) following Bolton (1980) and Davies-Jones (2008); then shows Cython equivalents with static typing, typed functions (cdef), memoryviews, contiguous memory views, bounds-check deactivation, OpenMP parallelism (prange), and scipy.optimize.cython_optimize brentq integration. Benchmark progression: 30% from compilation alone, 5x from typed variables, 200x with typed functions; wetbulb_cython achieves near 200x speedup compared to pure Python.

- **Climate_data_processing_using_xarray_dask_cython_mygeohub.ipynb** (https://github.com/PurdueCyberTraining/fairclimatewater/blob/main/DP8/Climate_data_processing_using_xarray_dask_cython_mygeohub.ipynb, Jupyter notebook): Complete workflow notebook combining Cython speedups with Dask parallelism for processing CMIP6 wet-bulb temperature data. Covers Dask chunking (`.chunk({'time':200})`), lazy computation semantics, single-machine vs distributed schedulers (dask.distributed Client), thread vs process workers and GIL implications, `xr.apply_ufunc` with dask="parallelized", multi-node HPC clusters via dask_jobqueue SLURMCluster with adaptive scaling, and best practices (avoid distributed unless memory-bound, start small, use the Dask dashboard, chunk sizing ~100MB, avoid excessive task creation). Applies wetbulb_cython function to 3D data arrays via apply_ufunc, saves results to NetCDF (wb_hist.nc, wb_ssp.nc), and computes statistical summaries: annual mean wet bulb temperature and 95th percentile changes between 2000 (historical) and 2100 (ssp585) scenarios, merged and exported to output.nc.

- **Pre-recorded YouTube lectures**: Two complementary videos from the Climate Dynamics Prediction Lab YouTube channel (https://www.youtube.com/watch?v=0GYdLmBU28s&t=707s and https://www.youtube.com/watch?v=Wa3bAaXsS-4&t=981s) providing video-based tutorials on using Cython and Dask for climate data processing, with narration and visual demonstrations of the code examples from the accompanying Jupyter notebooks.
